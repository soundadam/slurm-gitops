# docs 分两层：ref 给同事，work 给自己

**`docs/ref/` 只放实测的事实、用户已定的方案和列明的选项；倾向、待定问题和动作清单放 `docs/work/`。**
`ref/` 整个目录由 `tools/feishu_docs.py push` 同步到飞书，`ref/README.md` 是飞书首页；`work/` 不出仓库。

- 一句话写的是「倾向」「目前打算」，或者要等一个待定问题定下来才成立，就放 `work/`。
  选项本身、它的价格和代价放 `ref/`：列出几种买法不等于定了哪一种。
- `work/` 可以链 `ref/`，`ref/` 只链 `ref/`。越界的链接 `feishu_docs.py` 直接拒绝运行；
  `ref/` 里要用到 `work/` 里的某个事实，就把这个事实挪进 `ref/`，`work/` 改成指过去。
- 一件事在飞书上讨论出结论，就把它从 `work/` 挪进 `ref/`，改成现在时的事实，合并后 push。

- `ref/README.md` 先写现状拓扑、资源概况、要解决什么和目标拓扑，再列要先看的几点；细节各自单开一页，首页不展开。
- 二手货源、询价策略、对某个方案的个人判断不上飞书，放 `work/design.md`。

**为什么**：飞书上的读者打不开仓库，也分不清倾向和定论；倾向在飞书上被读到，就会被当成决定引用。
