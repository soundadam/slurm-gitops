# ADR-0003 按整节点、分阶段接入

## 决定

**D1** 一台节点要么完全由 Slurm 管（开 pam_slurm_adopt，没有作业就不能直接使用），
要么完全不接入。不存在「接入了但仍允许直接 ssh 上去跑」的中间状态，
只有开 pam_slurm_adopt 之前的短暂试运行除外。

**D2** 接入顺序：
1. 在 elon 上做测试控制器，只接 g18；
2. 在内网控制主机上正式部署，接入由自愿参加的组提供的大节点（g18、g19、g8、g9）；
3. 其余节点逐台加入，每台都要事先公告，并给一个缓冲期。

**D3** g4 在 GPU 修好之前不接入；g12–g14 在网络连通确认之前不接入。

## 理由

- 同一张卡上如果既有调度分配的作业，又有绕过调度直接跑的进程，调度出来的分配就不可信，
  这比完全没有调度还糟。
- 按整节点接入，可以逐台回退：出了问题，只需把那台节点拿出 Slurm、恢复 SSH，别的节点不受影响。
- 大节点卡多，调度带来的好处最明显；小节点只有 1–2 张卡，成员直接 ssh 上去用的代价也低。
