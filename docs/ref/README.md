# aalab 集群：计算与存储分离

这是 aalab GPU 集群整改和采购讨论用的资料。

## 现在

```text
     NAT 网关（对外只转发 SSH）
              │
      千兆交换机（只有一台）
   ┌──────────┼──────────────┬───────────────┐
 两台管理机      服务器 4 台        台式机 13 台
 NIS、家目录     g8 g9 g18 g19     全部 1G
```

- **17 台 GPU 节点，52 张卡。** 4 台是带远程管理的服务器，13 台是台式机。
- **数据 123T，散在 56 块本地盘上，将近八成满。** 没有备份，没有快照，没有配额。
- **数据在哪台机器上，作业就只能在哪台上跑。** 网络是千兆，搬 1T 要两个半小时以上。
- **身份靠 NIS，家目录在管理机上，** 都走同一台千兆交换机。

完整的现状见 [current](current.md)，每台节点的硬件和用量见 [inventory](inventory.md)。

## 要解决什么

1. **数据不绑在机器上：** 任何节点都读得到自己的数据，换一台机器跑不用搬数据。
2. **数据有备份：** 误删能自己找回；坏盘、坏机器不丢数据。
3. **网络跟得上：** 集中存放以后，节点读数据不能比现在读本地盘慢太多。
4. **账号和组管得起来：** 按组分配额和权限；以后接 Slurm 不用返工。
5. **一个人运维得过来。**

## 目标拓扑

```text
                      100G 核心交换机
     │100G       │25G         │25G ×2       │10G ×2      │10G           │10G
  热存储 st1   冷存储 st0    g18  g19      g8  g9     2.5G 接入交换机    控制节点 ×2
  家目录                                              │2.5G              身份服务
  正在用的数据   全部数据                              台式机 13 台
                热存储的备份

  现有千兆交换机：SSH、远程管理、出网，保持不变
```

- **热存储**是固态盘，放家目录和正在用的数据，所有节点直接读。
- **冷存储**是机械盘，装全部数据和热存储的每日备份，每 TB 最便宜。
- **节点的本地盘**清空后只当缓存。

## 先看这几点

- **能利旧的盘：**
  - g18 的 24T 企业盘并进冷存储；
  - g5、g19 的两块 16T 企业盘改作离线备份盘；
  - 各节点的固态盘清空后改作训练缓存，不用另买缓存盘。
- **热存储的固态盘是全单最贵的一项，** 而且今年涨价最凶。起步只买够装正在用的数据的量，盘位留着以后补。
- **不少部件可以买现货：** 交换机、网卡、机箱、控制节点。存数据的盘除外。
- **对成员变化最大的是数据路径和本地盘的用法，** 见[方案「热存储带来什么变化」](plan.md#热存储带来什么变化)。停机和时间安排见 [software](software.md)。
