# 身份认证与控制节点

这是和存储分开提的两件需求：替换 NIS 的身份服务，以及两台控制节点。控制节点上跑身份服务，以后也跑 Slurm 的控制器。控制节点用现有的两台管理机，不另买。

## 为什么要单独提

- **存储整改要用到组。** 热存储按组分配额和权限，NIS 里现在只有两个组，见 [current「身份与登录」](current.md#身份与登录)。
- **两台管理机现在身兼两职：** 身份服务和家目录都在它们上面。家目录挪到热存储以后，它们只剩身份服务这一件事。
- **以后接 Slurm，** 控制器要放在内网里一台稳定的机器上，不能放在某台 GPU 节点上。

## NIS 和两种替代

| 需要什么 | NIS（现在） | FreeIPA | OpenLDAP 加 SSSD |
| --- | --- | --- | --- |
| 所有节点 uid 一致 | 有 | 有 | 有 |
| 按课题建组、组长自己加减组员 | 能建组，但每次都要管理员改文件、重建表 | 有，组长可以被授权管自己的组 | 能做，要自己配权限 |
| 限制谁能登录哪台机器 | 没有 | 有（按主机的登录规则） | 要自己拼 |
| sudo 规则集中配 | 没有，逐台配 | 有 | 要装 sudo 的 LDAP 扩展，自己配 |
| SSH 公钥 | 放在 NFS 家目录里，家目录挂不上就登不进去 | 存在目录里 | 能存，要自己配 |
| 网上传的查询 | 明文，同网段谁都能查 | 加密 | 配上 TLS 以后加密 |
| 服务器坏了怎么办 | 有一台从服务器，现在是否在同步不清楚 | 两台互为副本 | 要自己配复制 |
| 管理界面 | 没有 | 自带网页界面 | 要另装，比如 LDAP Account Manager |
| 服务端跑在什么系统上 | 任意 | Rocky、Alma 这类 RHEL 系，或者用官方容器 | 任意 |

**迁过去收益在哪、不在哪：**
- **收益在：** 组能管起来；登录和 sudo 在一处配，改动有记录；能登录不再依赖家目录的 NFS；身份服务有两份。
- **不在：** 口令本来就不在 NIS 里，所以没有「口令泄露」这层收益。
  NFS 用的还是按 uid 信任客户端的方式：在任何一台节点上有 root 的人，都能在 NFS 上冒充任何 uid。这一点换了目录服务也一样。
  要堵上，得把 NFS 改成 Kerberos 认证。但这样训练跑几天、票据过期，就会读写失败，所以不采用。

## 切换怎么做，成员感受到什么

- **uid 和 gid 原样搬过去，** 各块盘上文件的属主不会乱。
- **SSH 公钥一起搬进目录，** 成员照常用公钥登录，不需要设口令。
- **逐台节点把 SSSD 装上、切过去，** 每台几分钟，不停机。当天 NIS 服务器照常开着，哪台切坏了马上切回来；观察一周再停 NIS。
- **单独一个维护窗口，** 不和冻结日、网络割接放在同一天。一天里出两种故障，很难分清是哪边出的问题。

## 管理界面

**不另做面板。**
- **账号、组、sudo、谁能登录哪台：** 用 FreeIPA 自带的网页界面。选 OpenLDAP 的话要另装一个。
- **存储：** TrueNAS 自带网页界面。成员看自己用了多少，由每晚生成的一页用量表提供，是静态页面，不用维护一个服务。

## 控制节点

**用现有的两台管理机 `nis.nca`、`nis-slave0.nca` 当控制节点，不另买。** 身份服务、Slurm 控制器和记账数据库都很轻，不需要新机器。

| 要求 | 为什么 |
| --- | --- |
| 两台 | 身份服务两份副本；以后 Slurm 控制器也是一主一备 |
| 不存数据 | 家目录搬到热存储以后，它们上面只剩服务，坏了重装就行 |
| 接在管理网上 | 身份服务和以后的 Slurm 控制流量都走管理网，千兆就够 |
| 接在 UPS 后面 | 身份服务停了，谁都登不进去 |

**两台轮流改装，身份服务不断：**
1. 家目录搬到热存储以后，两台都只剩 NIS。
2. 先重装 `nis-slave0`，装新的身份服务，把账号和组导进去；节点逐台切过去，`nis.nca` 上的 NIS 照常开着兜底。
3. 观察一周没有问题，停掉 NIS，重装 `nis.nca`，作为新身份服务的第二份副本。

**这一轮上线的：** 身份服务、时钟同步、监控告警。
**以后接 Slurm 时再加的：** Slurm 控制器主备、记账数据库、登录入口，都放在这两台上。
