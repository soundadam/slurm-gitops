# 系统整改与时间安排

硬件到位以后，系统上要改哪几步、每一步成员要做什么、要停机多久，以及现在放在各处的东西搬到哪里。为什么要这样改见[方案](plan.md)。

## 分几步

| 步骤 | 成员要做什么 | 停机 | 大约多久 |
| --- | --- | --- | --- |
| 0. 到货前 | 删掉自己明确不要的数据；报一下自己属于哪个课题组 | 不停 | 现在就能开始 |
| 1. 换网络 | 不用做什么 | 逐台停机：台式机约半小时，g18、g19 装网卡约一小时 | 一周左右，逐台排 |
| 2. 存储上线 | 不用做什么；所有节点上多出 `/project`、`/cold` | 不停 | 几天 |
| 3. 家目录搬到热存储 | 不用做什么；路径 `/home/nis` 不变 | 全实验室半天不能登录 | 半天 |
| 4. 全量冻结 | 冻结前两周是清理窗口；复制期间网络和盘都很忙 | 冻结日全实验室停机半天到一天 | 复制几天，时间见 [freeze-estimate](freeze-estimate.md) |
| 5. 搬进 `/project` | 把还在用的数据从冷存储拷到 `/project/<组>/`，改训练脚本里的路径 | 不停 | 冻结后 1–3 个月的宽限期内 |
| 6. 换身份服务 | 不用做什么；照常用公钥登录 | 不停，逐台切 | 一天，之后观察一周 |
| 7. 本地盘改作 `/scratch` | 宽限期结束前，本地盘上的东西自己确认已经在 `/project` 或冷存储上 | 逐台停机约十分钟 | 一天 |

- **第 1、2 步可以和第 0 步同时进行。** 第 3 步要等热存储上线。
- **第 3、4、6 步各占一个维护窗口，不放在同一天。**
- **第 4 步冻结日之后，本地盘只读挂载。** 在宽限期里它还是冷存储之外的第二份，直到第 7 步才清空。
  什么情况下能清空，见下面「本地盘什么时候清空」。

## 现在放在各处的东西，搬到哪里

| 东西 | 现在在哪 | 搬到哪 | 在第几步 | 对成员的影响 |
| --- | --- | --- | --- | --- |
| 家目录 `/home/nis`（3.9T） | 管理机 `nis.nca` | 热存储 | 3 | 半天不能登录；路径不变 |
| 账号和组（NIS） | `nis.nca`，`nis-slave0` 名义上是从服务器 | 两台控制节点上的新身份服务 | 6 | 感觉不到 |
| 两台管理机本身 | 跑 NIS 和家目录的 NFS | 家目录和身份都搬走以后，退役或改作控制节点 | 6 之后 | 无 |
| 各节点 `/data*` 上的数据（123T） | 56 块本地盘 | 全部冻结到冷存储；还在用的由主人拷到 `/project` | 4、5 | 路径变了，训练脚本要改 |
| 多人共用的公开数据集 | 好几个人各一份 | `/project/shared`，管理员保管 | 5 | 从一个地方读 |
| g18 的 24T 盘、g5 和 g19 的 16T 盘 | 各自节点上装着数据 | 数据冻结以后，24T 盘并进冷存储，两块 16T 盘改作离线备份盘 | 4 | 这三块盘要先冻结，见[冷存储](cold-storage.md#池怎么排) |
| 网络流量 | 全部走现有千兆交换机 | 数据走新的数据网；SSH、BMC、出网还走千兆交换机 | 1 | 无 |
| NAT 网关和端口转发 | `192.168.50.1` | 不动 | — | 无 |
| 从外部 S3 拉的数据 | 拉到本地盘 | 拉到 `/project` | 5 之后 | 无 |

## 本地盘什么时候清空

下面三条都满足，本地盘才能清空，改作 `/scratch`：

1. 冷存储上的冻结副本逐文件校验通过；
2. 宽限期结束；
3. 不可再生的数据（原始录音、人工标注）在冷存储之外还有第二份，见[冷存储「RAID 不是备份」](cold-storage.md#raid-不是备份)。

## 以后接 Slurm

这一轮不接 Slurm，成员的用法不变。接 Slurm 要的几个前提，这一轮都做好了：

- **数据不绑在某台机器上。** 任何节点都读得到 `/project`，作业不用指定跑在哪台机器上。
- **每台节点上的路径都一样。** `/home/nis`、`/project`、`/cold`、`/scratch` 在所有节点上是同一个意思。
- **uid 一致，控制节点已经在内网。** Slurm 直接用身份服务里的账号，控制器装在现成的控制节点上。
